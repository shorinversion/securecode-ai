Представляю SecureCode AI, учебный проект по аудиту безопасности кода. Его задача: проверить локальный репозиторий, объяснить найденные риски и предложить исправление. В этой демонстрации собраны результаты выполненных запусков. Рассмотрим устройство системы, пример SQL-инъекции, работу локальной модели и результаты эксперимента на открытом корпусе.

В системе используются статические инструменты и языковая модель. Они формируют кандидатов на уязвимости с указанием файла, строк и класса CWE. Аудитор рассматривает доказательства и оценивает находку. Архитектор готовит предложение исправления. Патч сохраняется отдельно от исходного репозитория. Перед применением требуется проверить его применимость, синтаксис и поведение на тестах. В проект входят командный интерфейс, серверный API, воркер и интеграции с GitHub и GitLab. Примеры охватывают Python, JavaScript, TypeScript и Go. Полнота анализа зависит от языка и класса уязвимости.

Первый пример посвящён SQL-инъекции. Статический анализ обнаружил один сигнал в уязвимом коде. На безопасном контрольном примере сигналов нет. После эталонного исправления во временной копии сигнал также исчез. Исходный репозиторий остался без изменений. Этот результат подтверждает работу правила на выбранном примере. Для оценки безопасности самого исправления нужны отдельные поведенческие тесты.

Следующий запуск выполнен с настоящей локальной моделью Qwen Coder на семь миллиардов параметров с четырёхбитным квантованием. Модель работала через Ollama на локальном адресе. Исходники в облако не передавались. Модель обнаружила кандидата на SQL-инъекцию в четвёртой строке файла app.py. Статический анализ указал на тот же участок. Запрос на генерацию исправления выполнился, однако пригодный патч получен не был. Поэтому результат исправления остался неопределённым. Проверки применимости, синтаксиса и безопасности патча в этом запуске не выполнялись.

Для эксперимента подготовлен корпус CVEfixes из шестисот случаев. На каждую языковую группу приходится по двести примеров. Уязвимые и исправленные версии объединены в пары. Родственные примеры находятся в одном разделе данных, чтобы исключить утечку между обучающей частью эксперимента и отложенной оценкой. Опубликованные измерения относятся к зафиксированной предыдущей версии проекта. Производный гибридный вариант завершил обработку трёхсот сорока семи случаев. В двухстах пятидесяти трёх случаях произошли ошибки сканирования. На отложенной выборке полнота гибрида составила двадцать семь целых восемь десятых процента, а Semgrep: тридцать два с половиной процента. Эти результаты не подтверждают преимущество гибрида. Отдельные эксперименты с DeepSeek оценивали прямые ответы модели. Они не измеряют качество полного конвейера SecureCode.

Материалы для воспроизведения включают README на русском и английском языках, закреплённые зависимости, демонстрационный notebook, описание корпуса и итоговый HTML-отчёт. В чистом каталоге проверены установка, сто сорок тестов продуктового среза и обе демонстрации. Полный набор проверок пока не завершён успешно. На сервере Cloud.ru размещены материалы проекта; серверный API прошёл проверку готовности. Публичный интерфейс онлайн-аудита ещё требует подключения и сквозной проверки.

Основной результат проекта: прототип объединяет инструменты анализа, локальную языковую модель и хранение доказательств. Реальный запуск подтвердил обнаружение SQL-инъекции на демонстрационном примере. Автоматическое исправление и преимущество над статическим анализом остаются открытыми задачами. Дальнейшая работа должна повысить надёжность обработки корпуса и проверить исправления на тестах безопасности. Все результаты и ограничения приведены в отчёте. Спасибо за внимание.
