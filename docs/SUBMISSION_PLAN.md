`01a07049-3886-7a52-bc78-e53900cc816f`. Координатор продукта продолжает P2.5

быть явной. Один writer на путь; правила моделей и ответов определены в
[DEVELOPMENT_WORKFLOW.md](DEVELOPMENT_WORKFLOW.md).

Readiness record допускает `NOT_READY | READY_FOR_SUBMISSION`; начальное
состояние — **NOT_READY**. Это не product scan outcome и не G0–G9 decision.
Record хранится рядом с delivery manifest, вне `artifacts/gates/G*/`.

Для `READY_FOR_SUBMISSION` нужны:

1. Exact commit/tree и hash комплекта, список файлов, версии и безопасные
   ссылки; все ссылки действительно доступны проверяющему.
2. Effective G2/G3/G4 и проверенная совместимость академического кандидата с
   ними; более поздние изменения не наследуют автоматически старый PASS.
3. Полные positive/negative semantic доказательства Python, JS/TS и Go;
   применимые инструменты, общие contracts и mandatory dual-lane coverage.
4. Реальный local-model demo, pinned model/server/profile/hardware; isolated
   execution без внешнего egress и без автоматического изменения checkout.
5. Независимое доказательство Python repair, existing regression tests,
   применимая security validation и отсутствие открытых release-blocking
   дефектов в включённых компонентах.
6. Фактически выполненный notebook и clean-room replay, отчёт с измерениями
   и ограничениями, README/dependencies/config/tests/data provenance.
7. Подтверждённые административные условия `SC-PROD-021`. Пользовательская
   дата сохраняется как отдельный факт, не как вымышленный ответ преподавателя.

   затронутые проверки после исправлений и действующая protected delivery.

Неприменимость допускается только по действительному условию контракта
