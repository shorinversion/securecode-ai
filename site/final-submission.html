SecureCode AI: итоговый отчёт

Итоговый проект, задача № 2. Состояние на 2 октября 2026 года. Исходное задание: docs/PROJECT_BRIEF.md.

1. Постановка задачи

Статические анализаторы (SAST) работают по жёстким правилам, дают много ложных срабатываний и не учитывают контекст, а передавать приватный код во внешние облачные API запрещено политиками безопасности. Цель проекта — прототип локального ассистента, который:

  • загружает исходный код Python, JavaScript/TypeScript и Go из локального репозитория;
  • анализирует его инструментами на базе ast и tree-sitter: синтаксическое дерево, поиск захардкоженных секретов, уязвимые версии библиотек, проверка сгенерированного кода;
  • с помощью мультиагентной системы на локальной квантованной LLM находит уязвимости (агент Аудитор) и предлагает безопасные исправления (агент Архитектор);
  • формирует отчёт .md/.html с классификацией по OWASP Top 10 и готовыми diff-патчами.

2. Решение

Git-ревизия (точный commit; Python, JavaScript/TypeScript, Go)
        │
        ├── детерминированные сканеры: AST/CST, правила для 35 CWE, секреты, зависимости (OSV)
        └── Поиск: LLM исследует код с помощью инструментов, независимо от сканеров
        │
        ▼
  граф доказательств (единый контракт) → Аудитор → Скептик → решение по находке
        │
        ▼
  Архитектор: исправление → проверка (git apply --check, синтаксис, повторный скан)
        │
        ▼
  отчёт: Markdown / HTML / JSON / SARIF, CWE, OWASP Top 10, фрагмент кода, diff
Агент Задача
Поиск Исследует код через инструменты репозитория и предлагает кандидатов в уязвимости
Аудитор Проверяет кандидата: достигают ли недоверенные данные опасной операции через границу доверия; вердикт требует уверенности не ниже 80%
Скептик Пытается опровергнуть вывод Аудитора: санитизация, безопасный API, недостижимый путь
Архитектор Предлагает минимальное исправление подтверждённой находки; патч проверяется до попадания в отчёт
Модуль задания Реализация
Загрузка данных native_sources.py: чтение файлов из неизменяемого Git-снимка, определение языка, лимиты
Библиотека инструментов cst_python.py, cst_ecmascript.py, cst_go.py (AST, CST, таблицы символов); secret_detection_*.py; dependency_scanning*.py (pip, npm, Go, OSV); 35 CWE-сканеров; trial_architect.py (проверка патча)
Единый контракт packages/contracts: RawSignal (правило/CWE, SourceLocation с путём и строками, ссылка на фрагмент кода ArtifactRef с SHA-256), Evidence, DiscoveryCandidate, FindingCase; JSON Schema в packages/contracts/.../schemas/v0.2.0
Оркестратор агентов product_audit.py, product_review*.py, investigation_runner.py: Поиск, Аудитор, Скептик, бюджеты и сессии инструментов
Auto-Fix trial_architect.py: модель предлагает правки строк, хост строит unified diff и проверяет его; --patch-dir сохраняет .diff, --open-pr открывает pull request
Отчёты trial_report.py (Markdown/HTML для человека), reports_render.py и reports_sarif.py (канонический JSON, SARIF)

Фрагмент кода передаётся в контракте по ссылке: ArtifactRef фиксирует SHA-256, размер и класс данных фрагмента, SourceLocation — путь и строки. Агенты получают сам фрагмент через инструмент read_evidence в ограниченном окне; это не даёт модели читать файлы вне выбранного контекста и исключает передачу секретов.

Модель подключается через OpenAI-совместимый интерфейс. Основной вариант — локальная Qwen 2.5 Coder 7B Instruct, квантование Q4_K_M в Ollama 0.34.4: доступ только через loopback, digest модели проверяется до и после вызова. Для больших репозиториев поддерживается DeepSeek по профилю, отдельно одобренному владельцем кода, с лимитом расходов.

3.2. Аудит реальных репозиториев

securecode analyze выполняет весь конвейер и формирует отчёт с фрагментом уязвимого кода, категорией OWASP Top 10 и проверенным исправлением Архитектора. Проверено на приложениях на Python, JavaScript и Go: подтверждены SQL-инъекции, внедрение команд, открытый редирект, обход пути и отсутствие проверки подписи JWT; ложное срабатывание CSRF отклонено Скептиком. Стоимость прогона на небольшом репозитории — $0.003–0.011. Пример исправления, открытого Архитектором как pull request: shorinversion/securecode-demo-app#1.

В конфигурации «сканеры + проверка» модель получает код и находки сканеров и, как Аудитор, подтверждает только те, где недоверенные данные действительно доходят до опасной операции. «Только модель» — базовая линия: та же модель без сканеров и без проверки. Одна проверка даёт precision 89,0%, но оценку 0,78 против 0,80 у модели без подсказок: подсказки делают модель осторожнее, и она пропускает часть уязвимостей.

Поэтому в конфигурации SecureCode решение принимается согласием трёх независимых проверок: Поиск (модель читает код без подсказок), Аудитор (та же модель проверяет находки сканеров) и вторая модель (тоже проверяет находки сканеров). В бенчмарке каждая проверка — отдельный запрос к модели; в конвейере securecode analyze ту же роль играют агенты Поиск, Аудитор и Скептик. Уязвимость попадает в отчёт, если её назвали минимум две проверки из трёх; голоса сравниваются по семействам CWE из иерархии MITRE, так что CWE-643 и её родитель CWE-91 считаются одной уязвимостью. Слабое хеширование решает детерминированное правило: оно распознаёт сам вызов hashlib, анализ потока данных здесь не нужен. Результат — 0,84 при precision 89,2% против 0,80 и 85,6% у лучшей модели без сканеров; с дешёвой DeepSeek Flash в роли второй проверки — 0,82. Разница с моделью без сканеров +0,037, 95% ДИ [+0,020; +0,056]: SecureCode и точнее, и находит больше. Голосование трёх моделей без сканеров не помогает (0,75–0,77), то есть выигрыш даёт именно сочетание сканеров и модели. Правила голосования не имеют параметров и пересчитаны по уже сохранённым ответам моделей, без новых запросов; выбраны они после первых прогонов, поэтому их стоит подтвердить на новом корпусе.

Попытка улучшить самого Аудитора переписанным промптом не удалась: с формулировкой «уязвимость считается и без недоверенных данных» он находит больше, но даёт много ложных срабатываний (0,71 против 0,78 на 1120 кейсах с ответом), и согласие трёх проверок с ним хуже (0,82 против 0,84). Поэтому в основной конфигурации оставлен прежний Аудитор.

Слабой модели подсказки сканеров помогают заметно (DeepSeek: 0,39 → 0,50). Простое объединение находок сканеров и модели хуже проверки (0,72 с gpt-oss-120b): оно добавляет все ложные срабатывания сканеров.

Модели с открытыми весами (gpt-oss, Gemma 4, Qwen) обычно разворачивают локально; здесь они вызывались по OpenAI-совместимому API neuraldeep.ru с теми же весами. Лучшая из них, gpt-oss-120b, опережает облачные модели, то есть локальный сценарий из задания реалистичен при достаточном оборудовании. Модели Qwen без режима размышления называют какую-либо CWE почти в каждом кейсе, и их оценка близка к нулю (0,05–0,15).

6. Ограничения

  • Полный агентный конвейер на крупных реальных файлах часто не доводит проверку до вердикта: на отложенной выборке CVEfixes анализ завершён в 42% случаев. Незавершённая проверка возвращает INDETERMINATE, а не «уязвимостей нет».
  • Локальная 7B-модель надёжно проходит сценарий демонстрации, но на произвольных репозиториях не всегда соблюдает строгий протокол Аудитора и Скептика; для больших проектов рекомендуется модель крупнее.
  • Исправления проверяются синтаксически и повторным сканированием, но не поведенческими тестами проекта.
  • Модели в бенчмарке, кроме полного конвейера, классифицируют файл одним запросом; на CVEfixes у всех конфигураций precision около 50% из-за устройства корпуса.
  • securecode scan (блокирующая проверка в CI) требует заранее одобренного хоста; для проверки предназначены securecode analyze, демо и notebook.

7. Выводы

Прототип выполняет требования задания: локальная квантованная модель в ролях Аудитора и Архитектора находит SQL-инъекцию, предлагает параметризованный запрос, исправление проверяется и попадает в отчёт с классификацией OWASP Top 10; инструменты покрывают AST, секреты, уязвимые зависимости и три языка. На двух открытых корпусах с эталонной разметкой сочетание детерминированных сканеров и языковой модели превосходит Semgrep и Bandit: на OWASP Benchmark for Python — 0,84 с открытой моделью gpt-oss-120b против 0,16, на CVEfixes — +16,2 п. п. recall при статистически значимой разнице. Согласие трёх проверок делает SecureCode лучше той же модели без сканеров (0,80): разница +0,037, 95% ДИ [+0,020; +0,056]. Открытые модели, которые можно развернуть локально, не уступают облачным: gpt-oss-120b — лучшая из моделей на OWASP. Главное направление развития — устойчивость полного агентного конвейера на крупных файлах (идеи в docs/IDEAS.md).
